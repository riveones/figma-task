# figma-task — мод Claude Code для страниц задач в Figma

Одной командой заводит страницу задачи в квартальном Figma-файле (Portal или Ecom) по стандарту design-lab:

1. Копия шаблона, имя `<эмодзи>  <KEY> – <название>`, место сразу после шаблона.
2. Jira-виджеты на всю цепочку задачи (корень → задача); ссылки для вставки — в панели с кнопкой Copy.
3. Доски флоу из скриншотов — из любого репо: прототип или ветка продакшн-репо, локально или на стенде.
4. Блок «🛠️ For dev»: элементы → компоненты продакшн-кита, с обязательной независимой перепроверкой.

**Для команды — [SETUP.md](SETUP.md)**: что делает мод и как его установить.

Процедура целиком — в скилле `figma-task-page` (`skills/figma-task-page/`: `SKILL.md` + `references/`). Имена людей, ключи Figma-файлов и прочее личное в репо не хранятся: эмодзи дизайнера и файлы квартала живут в настройках мода на машине.

## Что внутри

| Часть | Что делает |
|---|---|
| `/figma-task <JIRA-KEY> [portal\|ecom]` | Кладёт в поле ввода инструкцию со всеми вводными; Enter — старт. Без ключа открывает панель |
| «собери фигму для этой задачи» → инструмент `task_start` | То же без команды: ключ из просьбы или из ветки, вводные — в ответе инструмента |
| Подсказка после пуша | После `git push` ветки `feature/<KEY>-…` без страницы в Figma Claude один раз спрашивает «Собрать страницу <KEY> в Figma?» |
| `/figma-comments <JIRA-KEY>` или просто «проверь комментарии по DP-2871» | Разбор комментариев к странице задачи: мод сам находит страницу, план правок таблицей, правки по «да» — от текстов до обновления UI задачи с пересъёмкой, черновики ответов в треды |
| Панель «Figma task» | Шаги задачи (○ ◐ ✓ ✕), ссылка на страницу, ссылки для виджетов с Copy, черновики ответов в треды с кнопкой Post, переключение между задачами |
| Инструмент `task_progress` | Модель отмечает шаги — панель и сохранённый прогресс обновляются |
| Инструмент `set_designer_emoji` | Сохраняет эмодзи, который назвал человек, в настройках мода — второй раз не спрашивается |
| Инструмент `set_figma_file` | Сохраняет файл квартала (Portal или Ecom) после подтверждения человеком и запоминает, для какого квартала; прежний файл переносит в «Earlier Figma files». Когда по дате наступил новый квартал, `task_start` первым делом просит ссылку на новый файл; какой искать, подсказывает по дате и по файлу последней задачи |
| Инструмент `upload_screens` | Сам берёт URL у Figma MCP (`upload_assets`) и загружает PNG в прямоугольники. Берёт только `.png` с PNG-сигнатурой внутри папки проекта, только в Figma-файлы из настроек и только на https-адреса figma.com. Если URL взять не удалось (в auto-режиме вызов Figma MCP изнутри инструмента может остаться без решения классификатора), подсказывает, как получить их через `upload_assets` в самой сессии; с готовыми `uploads` только отправляет файлы |
| Инструменты `task_comments`, `draft_reply` | Читают открытые треды страницы через REST API Figma (с тем, к чему привязан каждый: пин на фрейме — к скриншоту или маркеру под ним) и готовят черновик ответа после правки. Человек видит каждый черновик целиком, с файлом и тредом, и отправляет его своей кнопкой Post в панели. Токен Figma — только в настройках мода |
| Агенты `flow-inventory`, `kit-mapper`, `kit-verifier` | Экраны и селекторы (прототип или ветка продакшн-репо); сопоставление с китом; перепроверка |
| `scripts/` | Playwright-обвязка (`lib.cjs`), контактные листы (`sheet.cjs`), вход для экранов за логином (`login.cjs` — входит человек), полный пример на DP-2871 (`examples/`) |

## Установка

Для команды — по [SETUP.md](SETUP.md): Figma MCP и мод из этого репо одной строкой в терминале (marketplace `sweed-design` — `.claude-plugin/marketplace.json` в корне), затем `/mcp` → `figma-remote` → Authenticate. Мод ставится на пользователя и работает в любом репо; эмодзи и файл квартала спрашивает на первой задаче и сохраняет сам (`set_designer_emoji`, `set_figma_file`). Обновление — `claude plugin marketplace update sweed-design && claude plugin update figma-task@sweed-design` (по версии в `plugin.json`).

Тем, кто правит сам мод, — из своего клона этого репо: `claude plugin install figma-task --marketplace ./ --scope user`. Мод читается прямо из папки и идёт за текущей веткой; после `git pull` или смены ветки — `/reload-plugins`.

## Настройки (`/plugin configure figma-task@sweed-design`)

| Поле | Что указать |
|---|---|
| Designer emoji | свой, любой, с которого не начинается ни одна страница файла. Мод спросит сам и сохранит |
| Portal / Ecom fileKey | текущие файлы квартала; пусто — мод найдёт по дате и файлу последней задачи, спросит подтверждение и сохранит (`set_figma_file`) |
| Earlier Figma files | fileKey прошлых кварталов через запятую — чтобы комментарии и перезаливка там работали после смены квартала. `set_figma_file` дописывает сюда заменённый файл сам. Мод пишет только в файлы из настроек |
| Figma MCP server name | как `/mcp` называет облачный Figma (по умолчанию `figma-remote`) |
| web-ui-portal-ci checkout | пусто: мод находит клон Portal сам — настройка, ссылка `external/` в design-lab, поиск в домашней папке по адресу репо в git (6 уровней, без `Library` и `node_modules`), предпочитая клон с `@sweed/fe-portal-kit` в `node_modules`; если таких несколько — спросит. Указать путь — чтобы взять другой клон |
| sd/web-ui-shop checkout | пусто: мод находит клон так же, по адресу `sd/web-ui-shop` (нужен для витрины, kiosk, `portal-cms`, `portal-shop-settings`). Указать путь — чтобы взять другой клон |
| Figma personal access token | для комментариев: Figma → Settings → Security → Personal access tokens, права File comments read + write. Хранится в защищённых настройках |
| Chromium for Playwright | если Playwright из репо хочет другую ревизию Chromium |

## Чего мод не делает

- Не отправляет ответы в треды сам: модель готовит черновики, отправляет человек кнопкой Post в панели.
- Не закрывает треды комментариев: REST API Figma этого не умеет — закрывает человек.
- Не привязывает Jira-виджеты: задачу виджета меняет только сам виджет. Мод даёт ссылки и кнопку Copy — вставить нужно руками (Import an issue or project).
- Не пишет в Figma из подагентов: в Claude Code подагенты кастомных типов не получают MCP. Агенты мода только читают код, все записи — из основной сессии.

## Разработка

При каждом изменении мода — поднять `version` в `.claude-plugin/plugin.json`: установки обновляются по версии (`claude plugin update` сравнивает её).

Процедура живёт в `skills/figma-task-page/` — правки вносить прямо туда. Репо публичное: ни имён людей, ни ключей Figma-файлов, ни токенов, ни адресов внутренних сервисов в нём быть не должно — всё личное идёт в настройки мода.

```bash
claude plugin validate plugins/figma-task
```

```bash
claude plugin validate .
```

```bash
claude plugin test plugins/figma-task
```

`tsc -p plugins/figma-task` — после того как движок загрузил мод (он кладёт типы в `.claude-plugin/types/`, папка в `.gitignore`). Если в сессии подключены сотни MCP-инструментов, их сгенерированные типы роняют `tsc` по памяти — тогда проверять копию мода с пустым `claude-code-mcp/index.d.ts`.
